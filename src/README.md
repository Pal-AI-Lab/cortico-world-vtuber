# io-vtuber

直播演出 World:消费弹幕与对局事件,输出混编 TTS 语音与 Live2D 动作的连续演出。
设计文档见 [vtuber_performance_module_design.md](vtuber_performance_module_design.md)。

## 分层

| 层 | 文件 | 职责 |
|---|---|---|
| L1 | `module.ts` 工具 `vtuber_act(script)` | 决定演什么。只见词表与文本;词表来自 bot 的演出包(见「演出包」) |
| L2 | `parser.ts` `states.ts` `orchestrator.ts` | 决定何时。beat 队列、gap、锚点时间轴、状态机、反射层 |
| L3 | `mixer.ts` + 演出包里的曲线(`pack.ts` 加载,`clips.ts` 只剩缓动与采样数学) | 决定参数值。60Hz 逐帧求值与仲裁 |
| L4 | `backend.ts`(经 `vts-client.ts`)+ 模型档案(模型目录里的 `cortico.profile.json`,`models/` 负责发现与校验) | IR → VTS `InjectParameterData` 注入,无状态;语义量→实机输入量的换算表是模型目录里的数据 |
| 旁路 | `diagnostics.ts` | 事件环 + 逐帧分层归因 + 录制导出。不挂时零开销 |

## 子进程隔离

演出引擎跑在**自己的子进程**里:装配层挂的是 `proxy.ts` 的 `VtuberModuleProxy`,
它 fork `child.ts`,真正的 `VtuberModule`(L1-L4 + TTS/对齐/声卡/演出流)整个在
子进程内运行。动机是帧率的尾延迟:60Hz 求值注入对同步阻塞极敏感,主进程上
mineflayer 寻路(A* 同步计算)、VLM 回包、任务收尾这类 100-500ms 的大块会直接
变成可见的参数跳变;隔离后有时钟的都在子进程,主进程只剩不带时钟的转发。

跨界协议在 `ipc.ts`,帧数据从不过界:主 → 子只有工具调用、outputTap 增量、
x-hot 配置快照与瘦事件信封(播出延迟地板用);子 → 主是日志/事件/
状态徽标的通知。工具回执语义与进程内一致;心跳状态行与控制台徽标走 300ms 级
推送缓存。子进程崩溃由代理自动重启(2s 退避),重启空窗内工具回执明说引擎不可用。
进程内组合仍然成立(module.test.ts 就这么跑),跨界链路由 proxy.test.ts 覆盖。

台本有三种行内记号(L1 契约):**【】阻断动作**——切开前后为两段语音,pulse 做完
整个 clip 才继续说;**<> 非阻断动作**——不切分,按它在文本里的位置落到播放时间轴上,
说到哪做到哪;**[] VoxCPM2 语气词**——白名单内的透传进 TTS 文本(音频里是真实的
笑声/叹息),表外的静默剥离。空【】没有断句语义;自然气口由两次工具调用之间的
间隔,提示词引导一次调用 1-3 段语音。

词表(L1↔L2 契约)是演出包的 `vocab.json`,由 `pack.ts` 加载并做别名归一;
`[]` 内可透传的 VoxCPM2 语气词属于 TTS 模型,清单在 `voice-tags.ts`。TTS 流水线在 `tts.ts`;语音经
`device-audio.ts`(audify/RtAudio)直接写本机声卡,播放时点从本地时间线直读、
驱动 lipsync 时钟。演出画面(字幕/动作标签/弹幕)由模组自带的 **overlay 页**渲染
(`overlay/`,由 `perform-stream.ts` 的 HTTP 服务在 `/overlay` 直接 serve,透明底):
OBS 加 browser source 指它即合成进直播画面。
SSE `/stream` 是 overlay 的内部数据面;对外渲染契约是 overlay 页。观众弹幕从同一服务的
WS `/danmaku` 进来。

## 字幕时间轴

一片语音开播时,`subtitle-cues.ts` 把整片文本切成若干条 cue(句末标点必断,长句在
逗号族就近断,零标点按单元数硬切),每条配一个显示区间,随 `subtitle` 事件交给
overlay,由它本地排程逐条上屏。时间来源四级:全量对齐 units(逐单元真实时刻)>
前缀对齐(前缀内真实时刻,之外从末对齐单元终点按速率外推并补停顿先验)> 片时长按
单元数比例 > 速率估计(`leadIn + 单元数 × msPerUnit + 停顿先验`,与 <> 锚点、跑飞门
预算共用同一套 msPerUnit 与先验,见「语速口径」)——没有 TTS/对齐时字幕照样有节奏,
只是时刻是估的。[] 语气词不进显示文本但占时间轴单元。埋点行 `[演出·字幕]` 印这一片
走了哪一级,估计档另附当时的速率与它的来源(实测分位 / 常数回落),前缀档附对齐到
第几个单元。

**cue 的 atMs 相对订阅端的接收时刻**,不是相对开播:发送时把开播坐标加上
`startedAt − now`。声卡给的开播时刻是投影出的可听时刻(写入领先量 + 设备延迟,
通常在未来一百多毫秒),订阅端把接收当开播就早那么多。负的 atMs 表示这条已经念到
|atMs| 处:overlay 立即上屏并从那里续增量,同一句已在屏上就原地续、不重建气泡。

**同一片会多次发送**,每次都是仍在显示区间内的全部 cue,overlay 清掉未触发的
定时器按新批重排:

1. 开播:流式片这一刻 `seg.result` 恒为 null(对齐在收流最后一步才出生),只能走
   估计档;非流式片已有 units/时长。
2. 播放中**跟播**(`startSubtitleTracker`):合成头领先播放头(RTF≈0.55),下一条
   cue 的音频在它该上屏之前多半已收到。按锚点抢跑同一套条件——cue 边界的估计
   时刻进入 2.5s 窗口、已合成时长盖过它 500ms——把截到边界单元(含它自己)的前缀
   送对齐,可采信的单元数长了就按前缀档重发。前缀对齐与锚点抢跑共用一次在途与
   300ms 覆盖增长闸(`alignSegPrefix`)。
3. 收流:全量对齐到手,这一段还在播就按对齐档重发(`收流重发`)。

收流后的字幕更新必须包含仍在显示区间内的 cue。负 `atMs` 表示该 cue 已开始播放，订阅端立即显示并从当前进度续播，避免重设定时器时遗漏正在播放的一句。

cue 内是**增量跟播**:每条带 `speakMs`(不含垫时的发声区间),overlay 先整句排版
定字号再清空,按发声进度线性放字——字幕跟着嘴走,没念出来的字不上屏;重发只会让
进度往前跳,不会把已上屏的字收回去。她被打断或音频被切(跑飞裁剪)时 `subtitle.cut`
让未上屏的 cue 作废、增量冻在切点、当前字幕提前淡出。

## overlay 画面(控制台面板)

「World › vtuber › overlay 画面」:推流链接(复制给 OBS browser source)、预览窗口
(iframe,`?bg=dim` 暗背景)、图层开关(字幕/动作气泡/弹幕)与字幕样式(字号/字重/
行数/字色/描边/底板/字体名)。配置存服务端(`worlds.vtuber.overlay`,装配层写回
config.json),改动经 `overlay.config` 事件热推给所有订阅中的页面——包括 OBS 里那份。
订阅方也可用 URL 参数按源覆盖图层(`?cues=0` 给正式合成关掉动作气泡)。
「试显字幕/动作提示/弹幕」把 demo 事件投进演出流,所有 overlay 一起看到。
注意:字幕要跟语音走,**不要**把 overlay 放进被延迟的游戏画面源;
两者必须是 OBS 里各自独立的 browser source。

`vtuber_act` 的参数流经**输出旁路**流式捕获:识别到调用头即逐字符
送 L2,解析、TTS 分片、演出与 LLM 生成全程流水线化。装配层把 `module.outputTap()`
填进主 session 声明(在 bot 那一侧接线)。不接 tap 时工具 handler
整段演出;台词路径等价,但积压闸门的口径不同——流式路径只在轮首裁决一次,
非流式路径每次调用都按轮首裁决。

正文累计至少 40 字后，句末标点可提前切出一片送 TTS，连续标点与闭引号归前片。`【】` 边界与流末始终冲刷残余文本，不受该门槛限制。已送入 TTS 的片段在后续失败或打断时不可回收，因此短句等待收集完整后合成。

## 配置

```json
"worlds": {
  "vtuber": {
    "enabled": true,
    "vtsWsUrl": "ws://127.0.0.1:8001",
    "streamPort": 7792,
    "ttsUrl": "http://127.0.0.1:8010",
    "audioDevice": "CABLE Input",
    "audioMirrorSystem": true,
    "audioSecondary": "default",
    "streamEnabled": true,
    "alignEnabled": true,
    "speechCapSec": 20,
    "silenceRemindSec": 10,
    "obsDelaySec": 0,
    "delayedSources": ["minecraft"],
    "yieldWindowMs": 500,
    "yieldFadeMs": 150,
    "live2dDir": "<VTS>/StreamingAssets/Live2DModels",
    "modelProfile": "auto",
    "decayGazeSec": [4, 6],
    "decayPoseSec": [10, 15],
    "decayEmotionSec": [20, 30]
  }
}
```

(另有 `ttsProfile` 与 `overlay` 两段由控制台面板写回,不必手填。)

演出包目录是配置项 `worlds.vtuber.packDir`(控制台「模型档案」面板可选目录,重启生效)。留空时
先找部署目录下的 `vtuber-pack/`、再找 bot 包目录下的 `vtuber-pack/`,都没有就用 `examples/vtuber-pack/`。

- 密钥:`.env` 中 `VTS_AUTH_TOKEN`(首次连接在 VTS 弹窗允许后写入)。
- **端口注意**:VTS Public API 默认占 8001,VoxCPM2 server 用 8010,演出流服务 7792。
  演出流端口被占用时最多顺延 5 个并打 `warn`(顺延本身就是"上一个实例没退干净"最早的旁证,不该只落 info)。
- `audioDevice` 主输出(默认 `CABLE Input`)。控制台下拉打开前现探播放设备;
  空=系统默认,`none`=不出声。
- `audioMirrorSystem` 副输出开关(默认开)。关则只走主设备。
- `audioSecondary` 副输出设备;`default`=当前系统默认(换耳机会跟着切)。
  主副落到同一设备时不重复写。
- `obsDelaySec` + `delayedSources` 是防先知穿帮:OBS 对游戏画面设固定延迟 N 秒后
  把 N 填进来,并列出被延迟画面对应的模组 id(如 `["minecraft"]`)。延迟源近期有事件时,
  演出反应不早于观众看到的画面(向事件库反查,只看信封的 source/ts)。0 或空=不设地板。
- `streamEnabled` / `alignEnabled` 是流式输出与逐字对齐的开关(都默认开、都热改),
  行为组合见「流式输出与 <> 锚点」一节;server 侧能力缺席时自动降级,不用手动关。
- `worlds.vtuber.ttsProfile` 是声线档案(参考音频/转写/生成参数),控制台面板改动后自动写回。
- `decay*Sec` 是三个 State 通道无新指令后滑回中性的随机区间(秒),控制台可热改。
- `live2dDir` 是 VTube Studio 加载模型的目录(`StreamingAssets/Live2DModels`),热改。
  模型档案按 `<live2dDir>/<模型目录>/cortico.profile.json` 在这里发现;模型文件仍由
  VTS 加载,模组只读它们做复检。
- `modelProfile` 选**模型档案**(见「模型档案」一节):一个档案 id,或 `auto` 按 VTS
  报的模型名认;控制台「模型档案」面板可换。指定的 id 在 `live2dDir` 下不存在时按
  `missing` 处理:画面照出(按模型名匹配,否则默认档案),日志打警告,面板标红。
  眼睑基线、眼球横轴取反、头部增益均由档案声明,不提供独立配置项。

模组 `start` 连上 VTS 后会关掉当前已激活的反应表情,避免开局残留;档案
`keepExpressions` 列出的装扮与道具表情保留。

## 演出包

参数集、演出词表与参数曲线是 bot 拥有的数据,不是模组代码:一个目录里三份 JSON,
`params.json`、`vocab.json` 与 `clips.json`,放在 bot 包目录下的 `vtuber-pack/`;`examples/vtuber-pack/` 是模组自带的
范例包,也是 bot 没带包时的默认包。加载与校验在 [`pack.ts`](pack.ts)(`loadPack` →
`PerformancePack`:`params` / `entries` / `aliases` / `pulse` / `sustain` / `gaze` / `fxIds`,
`resolveTag` 做别名归一与查词,`lint` 报非致命警告)。主进程代理与演出子进程各自读同一个包:
代理只用它渲染环境提示词(`{{vtuber.vocab}}` 洞由 `vocabTableRows` 按通道生成表格行),
子进程用它演出。

`params.json` 声明语义参数集:每个参数的 `unit`、`range`(混音台钳位区间)、可选的
`suggests`(建议接到的 Live2D 参数)、`losesIfMissing`、`probe`(自检探针幅度)。混音台的注视、
口型、眨眼、头部漂移写死用头部三轴、口型、眼睑、眼球四轴这十个参数,每个包都必须声明;其余参数
(尾巴、翅膀、腮帮……)随包增删,曲线只能驱动声明过的参数。

`vocab.json`:

```
{
  "entries": [ { "word", "channel": gesture|pose|emotion|gaze|fx,
                 "clipId", "lifecycle": pulse|state, "intensity"? } ],
  "aliases": { "别名": "词" }
}
```

每个词条的 `clipId` 必须存在于对应字典:gesture → `pulse`,pose / emotion → `sustain`,
gaze → `gaze`。fx 没有字典,它的 `clipId` 就是特效 id,模型档案的 `fx` 表按这些键声明
(`loadProfiles(dir, pack.fxIds)`)。强弱档是同一 `clipId` 配不同 `intensity` 的多个词。

`clips.json`:

```
{
  "pulse":   { id: { "id", "durationMs", "speechOnsetMs",
                     "tracks": { <契约参数>: [[ms, value, ease?], ...] } } },
  "sustain": { id: { "id", "hold": { <契约参数>: { "v", "settleTo"?, "settleMs"?,
                     "noiseAmp"?, "noiseHz"?, "phase"?, "noiseKind"?: sine|drift } } } },
  "gaze":    { id: { "id", "eyeX", "eyeY", "headX", "headY", "scanRadiusDeg"? } }
}
```

关键帧是展开写的,没有包络/序列 DSL;缓动名见 `clips.ts` 的 `EASES`。轨迹与保持的参数名
必须是契约参数(`models/contract.ts`),数值全是语义量(头部三轴是度,嘴角/眼睑/眉是
`[-1,1]` 相对中性偏移):同一份包跨模型不变,模型之间的差异只在模型档案的换算表里。

## 挂载

控制台「World › vtuber」页第一块是「挂载」:形象(VTS 连接)、声音(TTS server 进程)、
演出流(端口与订阅)各一行状态,各带自己的启停按钮。「一键挂载」把前两条一起带起来
——TTS 那头要加载权重、VTS 那头要人去点授权弹窗,两件事并行,完了报每条的结果。

VTS 首次连接要在它的弹窗里允许「Cortico Vtuber」插件(之后 token 记住免弹窗),连上顺带
复位残留反应表情。「测试动作」让形象点头+星星特效,走完整 L2→L3→L4 链路,是注入通不通的
最快检验。

## 演出测试、动作调参与日志

面板由本模组自己的面板 bundle渲染([`console/`](console/)),控制台按页签在它们之间切换,
一次显示一个;卡首一行摆着这一屏的读数(cue 数、注入帧率与丢帧率、日志条数)。
除挂载外还有:
- **动作调参**:改演出包的 `clips.json` / `vocab.json` 保存后按「重载参数」即刻生效
  (子进程从磁盘重读整个包并原地替换,不用重启;解析失败时旧包保持生效,回执带原因。
  环境提示词里的词表随下一次前缀重建更新)。面板标题行印当前包的目录。条目可单资产直发
  试跳(绕过台本/TTS);姿态/表情/看向是保持型,试完按「回中性」撤掉。关键帧是
  `[ms, value, ease?]`,第三位可选命名缓动(`smooth`/`in`/`out`/`back`)。
- **演出日志**:结构化事件环的文本投影(最近 400 条,面板 2s 增量轮询)——
  轮/拍/TTS 合成耗时/音频回执/状态 cue/韵律/打断。同一份也打进运行日志与
  操作者终端(`[演出·区域]` 前缀)。完整状态由诊断报表的 `state` 段按需提供，
  不写入周期性时间线事件。
- **演出诊断**:台本演出 + 分层归因与逐帧录制,见下文「演出诊断」。查动作/跳变问题
  从这里开始,不要去读日志。预置台本(输棋复盘等日常五条 + 对拍①-⑤各盯一个判别假设)
  可改可自写,「演出」走真实链路——TTS 出声在声卡,动作打进 VTS,回执点名断链项;
  「录制并演出」先开录再开演,把整段演出连同 VTS 对拍读回写进同一份导出文件。

## 注视模型

眼球不是"平滑滑向目标然后钉住",而是按眼动生理学生成的**保持—突跳**序列。
[`mixer.ts`](mixer.ts) 的常数都对得上文献,改之前先看这张表:

| 量 | 取值 | 出处 |
|---|---|---|
| 眼球参数满量程 ±1 对应角度 | 水平 ±18°、垂直 ±22° | 舒适眼在头内范围 COMR 中位数,Sidenmark & Gellersen 2019(**不是**生理眼动范围 45–55°:超出舒适范围就该由头去补,否则眼球贴在量程边界上会显得木偶) |
| 注视时长 | ex-Gaussian μ240 / σ50 / τ60 ms,下限 150ms | 实测均值 298ms、SD 64ms、右偏长尾,Cronin et al. 2020 |
| 扫视时长 | `D = 2.2·A + 21` ms | 主序列,Carpenter 1988 |
| 扫视速度曲线峰值时刻 | `clamp(22/D, 0.25, 0.5)` | 加速相约 20–25ms 与幅度无关,故幅度越大越正偏,van Opstal & van Gisbergen 1987 |
| 注视区内扫视幅度 | 指数分布,均值 = 注视半径 × 0.4 | 自由观看的 4.58° 是**跨物体**扫视;盯住一处是区域内扫描,幅度由这块东西多大决定 |
| 注视半径 | 每个 gaze 目标各自声明(`scanRadiusDeg`) | 一张脸的五官三角两三度(EyeSyn 2022 的 EYES/NOSE/MOUTH 驻留模型),一屏弹幕十几度 |
| 扫视方向 | 纵向分量压到 0.5 | microsaccade 显著偏水平,Engbert & Kliegl 2003 |
| 慢漂移 drift | 一阶低通白噪声,稳态 SD 0.22° | 瞬时速度 30–90 arcmin/s,Cherici et al. 2012 |
| 越界处理 | 朝注视中心反射 | 复现 microsaccade 与 drift 方向反相关(纠正漂移累积),Poletti & Rucci 2016 |
| 换目标扫视 | 主序列时长,但**下限 130ms** | 换目标时"总视线"一项瞬变(chat↔screen 差 48°)而头还滞后,算术式若直接生效,眼球会在**一帧内**从一头甩到另一头(诊断实测抓到 Δ1.71,86% 满量程)。下限 130ms 是**渲染率的让步不是生理值**:主序列给 34° 扫视只有 96ms,~60Hz 的注入链路只给它 5-6 个采样点,再短看起来就是瞬移 |
| 头动滞后眼动 | 60ms | 反应式转移 25–150ms。注意方向:**眼先动、头跟上**,只有自发/可预测的转移头才提前 |
| 头部跟随衰减 | ×0.85,不追到底 | 转向目标时头欠量 10–15°、回归斜率 ≈0.6 |

**眼头协同不需要单独的 VOR 状态机**,由一个式子给出:

```
眼在头内 = 总视线 − 头已经转过的部分
```

头还没跟上时眼先顶上去(顶到满量程就停在那儿等头,即大幅转向的阶梯式行为),
头追上后眼自然回落到机位设定值。这就是"眼先冲到位 → 头跟上 → 眼回中",
总视线全程锁在目标上。测试见 `tests/worlds/vtuber/mixer.test.ts` 的两条 gaze 用例。

## 眼睑:idle 为主,表情帧接管

空闲期的眼睑归属由档案的 `idleBlinks` 决定。`true`:平时眨眼来自模型自带的 idle
动画(`.vtube.json` 的 `FileReferences.IdleAnimation` 指向的 motion3 直接驱动
`ParamEyeLOpen` / `ParamEyeROpen`;注入端恒发 `faceFound: false`,该动画持续播放),
没有眼睑写入的帧混音台完全不碰。`false`:L3 全程持有眼睑,空闲期也写中性位并自己
排眨眼。模型复检会读 idle 动画的曲线表,与 `idleBlinks` 不一致时报警(空闲期双重眨眼,
或整场不眨眼)。`ParameterSettings` 中的 `UseBlinking: false` 仅关闭追踪期间的 VTS
自动眨眼,不影响 idle 动画。

clip 写了眼睑分量的帧(眯眼表情、瞪眼动作、`眨单眼`)则由注入接管,靠两件事撑住:

1. **基线换算(L4)**。VTS 输入参数 `EyeOpenLeft` 在**无追踪时基线是 0**,而模型
   把它映射到 `ParamEyeLOpen` 的一段区间(Cubism 模板是 `[0,2]`)——输入 0 = 全闭,
   正常睁眼落在输入区间中段的某个值,**这个值随模型作者的映射而不同**。clips 里的
   眼睑值是"相对睁眼的偏移"(-1 全闭、+1 瞪到最大),`VtsBackend` 按档案
   `wiring.EyeOpenLeft/Right` 的 `neutral + 偏移 × scale` 换算成绝对量再注入。
   直接 `add` 整条曲线都落在错误半区:负偏移全闭而不是眯,小正偏移是空操作——
   真机上"该眯眼时整只眼闭掉"就是它。中性值取错一个档位就是**永久半睁**,所以它
   属于模型档案而不是全局配置。偏移回 0 时发的正是睁眼位,与 idle 基线对齐,
   移交缝隙里不会卡在半闭。
2. **接管期眨眼(L3)**。参数持有期间 idle 动画无法驱动眼睑。帧内存在眼睑写入时,
   混音台生成补偿眨眼:
   总时长卡通档 233ms、闭 75ms / 张 158ms 的闭快张慢、间隔 2s 起步右偏分布,
   闭合作用在 `(1+偏移)` 的乘性上(眯着眼也能眨)。没有眼睑写入的帧完全不碰。

眼睑输入上的 VTS 平滑(`ParameterSettings[].Smoothing`)必须为 0:233ms 的眨眼过不完
平滑就被抹平,单眼闭不上。模型复检对此报错级警告。

踩过并由上面两条修掉的两种写法,留档防回退:

| 写法 | 症状 | 根因 |
|---|---|---|
| 逐帧 `add` 一个微小的"眼睑随视线上下微跟" | **眼睛一直闭着** | 基线 0,加小量还是 ≈0 |
| 只在眨眼那 233ms 里 `set (1+delta)·(1-闭合度)` | **长时间闭眼、偶尔瞪两下** | 基线错 + 移交缝隙 |

(眨眼文献值还有没用上的:率挂"是否在出声"、子句边界 +52ms、>17° 转头诱发、
Bell 现象眼球向下转,在 git 历史里。)

呼吸归 VTS(`UseBreathing → ParamBreath`),没有接管。

## 韵律层

说话时的头动**不是**固定正弦律动。真实结构是分层的:`0–2Hz` 是与语音无关的姿态漂移带
(由混音台的环境漂移层与 `轻轻摇摆` 提供,见下节),`2Hz` 以上那层才与韵律相关。而且这一层要做成**事件级**
而非连续映射——语音→头动本质欠定:头动能解释 F0 方差的 63–88%,反过来 F0 只能解释
头动的 25–50%,连续映射最多复现一半方差。事件级的条件概率反而很稳。

幅度全都压在 ±3° 量级(韵律相关的点头包络实测就这么小),而且
**放大头动幅度并不会更好**:双倍头动的语音可懂度与完全不动头同样差(Munhall et al. 2004)。

| 事件 | 做什么 | 出处 |
|---|---|---|
| 句首(停顿 >350ms 后开口) | 提前 260ms 走 `speech_onset`:**先轻微下压、再在开口那一刻上扬点头** | 同一说话人在 50 句问候语里 >70% 复现,Graf et al. 2002 |
| 句内重音 | 概率 0.8 排一个头动基元:`accent_nod` 52.5% / `accent_nod_overshoot` 22.5% / `accent_swing` 25% | P(任一主要头动 \| pitch accent)=80%,三种基元占 42/18/20%,Graf et al. 2002 Table 4 |
| 强重音(片内排名前 1/3) | 概率 0.7 排 `accent_brow` 抬眉,起点比重音**提前** 60ms | P(抬眉 \| 强重音)≈70%;起点 -60ms、准备相 270ms、总时长 300–600ms,Flecha-García 2010 |

重音从 TTS 的振幅包络里找(局部极大 + 电平门 0.6 + 相邻至少隔 320ms)。用能量而非 F0
是因为 TTS 只给了振幅包络——能量对头动的解释力弱些(R²≈0.32 vs F0 的 0.63),但重音位置
基本对得上。实测在语音状包络上是 **1.4–1.5 次/秒、间隔中位 880ms**,不挤堆。

"强重音"**按片内排名取前 1/3,不能用绝对电平门**:包络是按 p95 归一化的,峰值天然都挤在
0.8–1.0,绝对门等于对所有重音都成立,抬眉会变得太频。(排名这一步是工程化取法,非文献值。)

抬眉必须**早于**重音,所以只能在开播时预排整片,不能靠逐帧在线检测。
抬眉的提前量实测离散度极大(σ≈458ms 远大于 μ≈63ms),所以排期时加了数百毫秒抖动,
不当精确偏移用。`accent_swing` 用**负 intensity 镜像**随机甩向两侧,不必写两份资产。

韵律走独立通道(`mixer.prosodyCue`),与 gesture 共用资产格式但**不参与 ducking**——
它每句话都来好几次,若压低同参数的 State 贡献,前倾/可怜这些保持姿态会被反复抽掉再恢复。
硬打断时 `dropPendingProsody` 丢掉还没起跳的,避免已作废语音的伴随头动继续发生。

## 头部所有权与环境漂移

VTS 注入会替代 idle 对同一输出参数的控制，不与 idle 叠加。停止注入约 1s 后
idle 重新取得控制权，交接会产生可见参数跳变。

混音台因此对头部三轴**每帧必写**，idle 的头部动作带由
`AMBIENT_HEAD` 的 1/f 环境漂移顶替(X ±6.5° / Y ±3.5° / Z ±2.5°,幅度约 idle 的七成;
`轻轻摇摆` 等 pose 在其上叠加)。漂移分量保持在 0.1–0.7Hz。idle 的眨眼、目光游移与
呼吸不受影响。诊断分层里它叫 `ambient`,观感调 `mixer.ts` 的 AMBIENT_HEAD 三行。

## 身体摇摆

`sway` 的摆动波形是 1/f 漂移噪声(`noiseKind: 'drift'`)而不是正弦:真人重心摇摆的
功率谱斜率实测 ≈ -1、95% 功率在 1.14Hz 以下(Yamamoto et al. 2015),正弦那种规律
往复读起来是节拍器。实测一周期后的自相关正弦是 1.000、漂移是 0.579。

## 模型档案(换 Live2D 模型时唯一要改的东西)

演出层(L1-L3)只写**语义量**:头部三轴是度、嘴角与眼睑是 `[-1,1]` 的相对中性偏移。
从语义量到实机的换算取决于模型作者在 VTS 里怎么接线,而**每个作者的接法都不一样**。
这份差异整个收在模型档案里;演出包(词表与曲线)不随模型变。

**档案是模型目录里的数据,不在仓库里。** 一份档案是 `cortico.profile.json`,放在该
模型自己的目录下(`<live2dDir>/<模型目录>/cortico.profile.json`,`live2dDir` 即 VTS 的
`StreamingAssets/Live2DModels`),与模型文件一起走。仓库不含任何模型文件、模型名或
逐模型的换算数值;`models/` 只有契约、校验、发现与复检代码:

| 文件 | 内容 |
|---|---|
| [`models/contract.ts`](models/contract.ts) | 契约(建议模型至少接哪些输入)、档案类型、换算的数学形式、默认档案 |
| [`models/schema.ts`](models/schema.ts) | 档案 JSON 的逐字段校验;错误带字段路径,拼错的参数名在加载时抓住 |
| [`models/registry.ts`](models/registry.ts) | 发现 `<live2dDir>/*/cortico.profile.json`、按 id / 模型名定档 |
| [`models/vtube-check.ts`](models/vtube-check.ts) | 模型目录只读复检:档案与 `.vtube.json`、表情、idle 动画对不对得上 |
| [`models/selfcheck.ts`](models/selfcheck.ts) | 接线自检:实测每条接线与斜率,验证写好的档案 |
| [`models/LIVE2D-ADAPTATION.md`](models/LIVE2D-ADAPTATION.md) | 给新模型写档案的步骤与规则 |

档案字段:

```
{
  id, label, backend: "vts", vtsModelName,
  wiring:  { <契约参数>: { neutral, scale, clamp, invert, aliasTo } },
  unsupported: [<契约参数>],
  fx:      { <特效 id>: { file, durationMs } | null },   // 键取演出包 fx 通道的 id;没写的按 null
  keepExpressions: [<表情文件名>],
  idleBlinks: true | false,
  caveat?: "..."
}
```

换算是 `wire = clamp(neutral + 语义值 × scale, lo, hi)`,外加 `invert`(这一轴反向接线)
与 `aliasTo`(改发到别的输入参数;多路并一路时取均值);`wiring` 里没列的参数原样直发。
`unsupported` 是这个模型演不出来的语义参数。`fx` 是每个特效标签在本模型上的表情文件
与自动关闭时长,`null` 表示没有这个特效——标签被丢弃并提醒一次;演出包 `fxIds` 里的
`fx` 是稀疏表:包里有而档案没写的特效按 null(没有这个特效),档案写了包里没有的键只在控制台警告,不影响加载;`wiring`/`unsupported` 引用包外参数同理。`keepExpressions` 是启动复位时保留的装扮表情。`idleBlinks`
是模型自带 idle 会不会眨眼:`false` 时 L3 全程持有眼睑、空闲期也自己排眨眼(见「眼睑」
一节),idle 不眨眼的模型无需另写 motion3。`vtsModelName` 是 `.vtube.json` 的 `Name`,
`auto` 定档按它匹配。

**发现与定档。** 连接 VTS 时和控制台「模型档案」面板每次读状态时重扫 `live2dDir`,
目录与档案文件都可热改;坏文件与重复 id 记进面板的错误列表,不影响其余档案。
`worlds.vtuber.modelProfile` 是档案 id 或 `auto`:

| 配置 | 结果 |
|---|---|
| 存在的 id | `configured`,用它 |
| `auto`,模型名匹配到档案 | `matched` |
| `auto`,没匹配到 | `fallback`:默认档案(按 Cubism 模板接线猜的换算,没有特效),日志记一次警告 |
| 不存在的 id | `missing`:画面照出(模型名匹配或默认档案),日志打警告,面板标红 |

VTS 里切换模型(`ModelLoadedEvent`)重新定档。面板把实机当前加载的模型名标在对应选项上。

**模型复检(只读)。** VTS API 不返回 `ParameterSettings`,所以连接时与面板读状态时
直接读模型目录里的 `.vtube.json`、idle motion3 与表情文件,报告:`Name` ≠
`vtsModelName`(auto 认不出);眼睑输入上 `Smoothing > 0`(必须为 0);`MouthOpen` 上
`Smoothing > 0`(建议 0;头部三轴的平滑不报,曲线本就按带平滑的模型手调);`fx` / `keepExpressions` 引用的表情文件不存在;
idle 动画驱动眼睑而 `idleBlinks: false`,或反之。只报告,不改文件。

**档案可调范围**:注入值的增益、中性位、取反、合并输入、缺失参数、特效文件与
眼睑所有权。模型侧的 `ParameterSettings`(输入区间、输出区间、平滑值)无法通过
VTS API 读取或写入,只能直接修改 `.vtube.json`。

**档案契约是建议性能力声明。** 不满足契约的模型仍可挂载;无法表示的参数在注入端
丢弃并记录一次警告。
**词表不会因此收缩**——人格还是会说"鼓脸颊",只是这一层把它咽掉。下层的能力缺口
不该反向重塑上层的表达空间,否则同一个人格在不同模型上能说的话就不一样了。

### 接线自检

VTS **查不到输入→输出的映射表**(`ParameterSettings` 不在任何 API 的返回里)。
`InputParameterListRequest` 只答"我认识 `BrowLeftY` 这个输入",不答"这个模型把它接到了哪"。
所以接线断开是一种**静默失败**:注入照发、照被接受、落地为零,不报错也不动——
只提供合并眉毛输入、或没有腮帮参数的模型上,眉毛与腮帮就是这样。

自检的做法是实测:逐个注入契约参数、读回 `Live2DParameterListRequest`,看什么跟着动、斜率多少。
控制台「模型档案」面板上一键跑,约一分钟。它的角色是**验证**:档案先按模型文件写好
(`LIVE2D-ADAPTATION.md`),再用自检核对实际增益。两个坑各有对策:

- **物理余振**:头一动,头发/兽耳/翅膀的物理会晃出几十个参数。按**相对强度**筛
  (只留最强项 8% 以上),因为余振比真接线小两个数量级,但绝对值能过阈值。
- **自走参数**:呼吸与 idle 动画驱动的参数与注入无关地一直在变。全零基线下连采几次,
  仍在变化的参数不计为响应,防止把自由运行参数归入无关探针。

跑出来的斜率就是档案里 `scale` 的倒数,`@0` 的读数就是 `neutral` 的依据。

## 输入参数名单过滤(别让一个参数名毁掉整帧)

连上 VTS 后模组会查一次 `InputParameterListRequest`,把实机认识的输入参数名交给 L4;
不在名单里的一律不发。原因是**注入一个不存在的参数会让整条注入请求被拒**(`APIError 453`),
连同同一条请求里其他正常参数一起丢 —— 一个参数名就能让那一帧全灭。

模型的 `.vtube.json` 可能包含仅由外部面捕程序提供的参数，如 `BrowAngleL`、
`BrowAngleR`、`MouthShrug`、`JawOpen` 与 `MouthWiden`。注入参数必须以运行时
`InputParameterListRequest` 返回的名单为准。

三条防线:

- 名单为空时按查询失败处理，不执行过滤；VTS 正常模型必有内置输入参数。
- `add` 与 `set` 两条请求独立发送，一条失败不阻止另一条。
- **名单到手之前不发帧**(`beginParameterSync`)。连接刚成到名单查询返回之间有
  发帧窗口会使未知参数触发 API 453 并拒绝整条请求。

被摘掉的参数名会在演出日志里报一次(`[演出·注入]`),不会每帧刷屏。

## 帧率:定时器量子与注入流水

「动作幅度够了却看不见」「短促动作发糊/瞬跳」十有八九是帧率,查诊断报表的
`window.evalHz` 与 `inject.sentHz`/`dropPct`,两级各有一个已经踩过的坑:

- **求值(L2 tick)**:Windows 的系统计时器量子约 15.6ms,`setInterval(16)` 经常
  落到两个量子——本机实测请求 60Hz 只拿到 **36Hz**,帧间隔中位 31ms,一切曲线的
  单帧步长翻倍,诊断里成排的 6-8°/帧 pulse"跳变"就是它。现在请求 8ms(贴着量子
  每拍都到,实测 ~64Hz)。最小帧间隔限流只挡 1ms 分辨率下的空转,阈值必须远小于
  目标帧间隔(6ms):真机进程里 WS 回包会打散定时器唤醒相位,阈值贴着目标(曾取
  13ms)会把一次 12.9ms 的早到跳过、下一次落到下个量子,凭空造出 28-31ms 长帧。
  评估多了不亏,发送节奏由 L4 自己限流。
- **注入(L4)**:每帧 add/set 两条请求**并发**发(串行两次往返实测把注入压到 19Hz、
  丢帧 54%——340ms 的点头只落到六个采样点,峰值被跳过,再过一遍 VTS 平滑就什么
  都看不见了);且按帧**双帧流水**——单帧在途时吞吐被 VTS 往返时间(实测 25ms
  上下)钉死在 ~35Hz,两帧在途才吃得满求值率。流水满时最新帧进候补位,回执一到
  立即补发,真正丢掉的只有被更新覆盖的候补帧。

## 真机校准清单(模型侧,代码改不了)

这几项在 VTS 的「模型设置 → 参数设置」里改,`.vtube.json` 的
`ParameterSettings[].Smoothing` 就是它。**动作发糊要先查这里,不要去加
演出包曲线的幅度**——文献很明确:放大头动幅度不会更好,双倍头动的语音可懂度
与完全不动头同样差(Munhall et al. 2004)。模型复检(「模型档案」一节)读的就是这张表,
眼睑与头部/口型两档的越界会在连接时报出来。

另外注意:这份表是**模型配置里的**映射,不等于实机真有那个输入参数
(`BrowAngleL` 这类见上一节)。

| 绑定 | 要求 | 为什么 |
|---|---|---|
| `EyeOpenLeft/Right`、`MouthOpen` | **0** | 眨眼 233ms、口型逐帧,任何平滑都抹平;眼睑有平滑单眼闭不上 |
| `FaceAngleX/Y/Z → ParamAngle*` | 0,至少三轴相同 | 头部 pulse 340ms;三轴不对称时纯 X 振荡的 `摇头` 与韵律基元 `accent_swing` 会明显比 `点头` 迟钝 |
| `EyeRightX/Y → ParamEyeBall*` | 个位数以下 | 扫视要脆 |
| `CheekPuff → ParamCheekPuff` | 个位数 | `得意` 的鼓腮起势慢半拍就是这里高了 |
| `MouthSmile → ParamBrowLForm/RForm`(眉形跟笑意) | ≤ 20 | 平滑上限 100 会拖出秒级延迟,情绪转折时眉毛跟不上嘴 |
| `FaceAngleX → ParamBodyAngleX` | 可保留作者值 | 身体跟随头部,本就该滞后 |

另外两项不是平滑、但同属"只能在模型侧对齐"的,都进档案的 `wiring`:

- `EyeRightX → ParamEyeBallX` 的输出范围是否倒序 → `invert`。
- 眼睑、嘴角与眉毛的输入→输出映射决定"正常睁眼 / 中性嘴角 / 中性眉"落在输入区间的哪个值
  → `neutral` 与 `scale`(Cubism 模板的 `in[0,1] → out[-1,1]` 或 `[0,2]` 中性在输入 0.5,
  作者改过映射的模型要按 `.vtube.json` 重标,跑一次接线自检核对)。
  基线 0 直发的对拍实录:微笑 +0.64 只渲染出 +0.28、眉毛 +0.12 输出成 -0.76(方向反)、
  皱眉钉在满格之外;最坏的是表情放手后嘴角以"输入 0 = 满格皱眉"钉住 ~1s,
  再被 idle 动画抢回时单步猛弹 Δ1.5——"表情结束时的跳变"就是它。
  换算后放手落点 = 输入 `neutral` = 中性,交接残余只剩 idle 自身振幅的量级。

## 演出诊断(排查"形象看起来不对"的正道)

[`diagnostics.ts`](diagnostics.ts)。**要数字,不要读日志。** 一条按时间顺序的文本流
回答不了"这个动作的幅度到底有没有到模型上""这一帧是谁把值拽走的",所以诊断给的是:

| 段 | 内容 | 能回答什么 |
|---|---|---|
| `window` | 求值帧率 | 混音台自己跑得对不对 |
| `inject` | **真实注入帧率、丢帧率**、实机不认的参数名 | 「短促动作看不见」——340ms 的点头如果只落到六七个采样点、再过一遍 VTS 平滑,峰值就没了 |
| `params[*].peakBy` | **每层的峰值贡献**(state/pulse/prosody/blink/follow/override) | 定位被其他层压低的贡献,如 prosody 峰值 3° 而最终值 `p2p` 只有 1° |
| `params[*].jumps` | **最大跳变排行 + 归因**:每次跳变带各层的同帧变化量与 ducking 系数变化 | 「有跳变」——绝对值最大的那层就是元凶 |
| `state` | 编排器与混音台的当前全貌(含各 State 通道**剩余超时**) | 「现在到底挂着什么」 |
| `events` | 结构化事件环(数值时间戳 + 跨度) | 时序对不对得上;控制台那条文本日志就是它的投影 |
| `capture` | 按需录若干秒的**逐帧原始值** | 上面都不够时,自己复算 |
| `probe` | 录制窗口内**从 VTS 读回**的两条序列:合成后落在模型上的 Live2D 输出参数(`Live2DParameterListRequest`)与 VTS 输入参数实时值+默认值(`InputParameterListRequest`),约 20Hz,与 capture 同一条时间轴 | 逐帧比较 capture 与 probe,定位注入端或 VTS 端(映射/idle 让位/表情/物理)的跳变;`inputDefaults` 验证 add 注入的基线假设 |

跳变**用排行而不是阈值**:阈值要按参数逐个调且容易调偏,排行直接把最坏的摆在最前面。

**报表每 5 秒覆盖写进 `<bot>/data/vtuber-diag/latest.json`**(该目录已 gitignore),
出问题时不用先去点按钮——直接看那个文件。控制台「演出诊断」面板另有「录制并导出」,
录 N 秒逐帧值写成带时间戳的单独文件。诊断不挂时混音台零开销(`attachDiagnostics(null)`)。

`ducking` 在 pulse 起始帧将同参数的 State 贡献从 1.0 立即降至 0.3，并在 1 秒内恢复。
「前倾」与点头叠加时会产生 6.3° 头位跳变；`tests/worlds/vtuber/diagnostics.test.ts`
通过真实混合链覆盖该行为。

## 语音链路

TTS 音频经 `device-audio.ts`(audify/RtAudio,WASAPI/CoreAudio/ALSA)直接写本机
输出设备。主输出 `audioDevice`(默认 `CABLE Input`)指到虚拟线,OBS 将对应输出
作为麦克风采集;空=系统默认,`none`=不出声。`audioMirrorSystem` 是副输出开关
(默认开);开着时再写一份到 `audioSecondary`(`default`=当前系统默认,换耳机会
跟着切)。主副落到同一设备时不重复写。
TTS 出来的是单声道,按设备通道数复制铺满(立体声设备两路同响)——只写通道 0 的话
下游听到的是单边有声。

sink 内部是一条按墙钟推进的连续样本时间线:泵保持写入领先播放位约 100ms,没有语音
的空当补静音。流式合成的分块(PCM16)边收边入队,开播/播毕时刻从时间线直读
(不需要任何回执对时),lipsync 与重音锚在实际写入位置 + 设备延迟上。设备打不开
(没装原生层/无声卡)自动退化为纯静音时间线,演出照常推进。

时间线的原点锚在主输出声卡的**实际消费位**上。audify 的输出队列无界、`write()` 从不
阻塞,声卡回调每拍(`streamTime` += 帧长)弹一帧、没帧就放静音;写入按墙钟推、消费按
声卡晶振走,两个时钟一差队列就只长不短,队列有多长声音就比字幕和嘴型晚多少。泵每拍
读一次 `streamTime`:新增拍数里能弹掉的帧记为消费,余下的拍是空转,`originWallMs`
对齐到「已消费样本数换算回墙钟」。锚在消费量而不是拍数上是关键:泵停一下(事件循环
卡住超过 AHEAD_MS)时声卡把队列饿空后放的静音同样计拍,按拍数锚会把那段静音记成已播,
之后补写的帧永远多出一段积压,一次卡顿一个台阶,整场累计成秒级延迟。按消费量锚,同一
下卡顿变成时间线整体后移(声音里是一段静音),并落一条 `声卡空转` warn 进滚动摘要。
副输出另有自己的表,按同一套记账算真实积压,超过 250ms 就丢一帧追相位。

主、副输出分别管理重试。驱动可在 `start()` 与首次 `isStreamRunning` 成功后异步停止流；WASAPI 渲染线程退出时会将 RtAudio 状态置为 STOPPED。
副输出采用 0.5→8s 退避，五次未能稳定启动后放弃该路，继续使用主设备。主输出持续重试：前两次失败立即重开，之后以 0.5→5s 指数退避；等待期间推进静音时间线，由泵每 500ms 检查重试。连续第三次失败起，日志改为每 15s 节流的 warn，报告本地设备未输出声音。连续运行 3s 后清除失败记录。

流式预取使下一片的合成分块提前入队,轮到播放时可立即出声,因此
**整轮只有第一片承担 TTFA**。硬打断会中止在途合成请求并释放 server 解码任务;
音素感知切断直接在样本队列的切点处拼接衰减尾巴(切点提前量 `CUT_LEAD_MS` 大于
写入领先量,切点恒落在还改得动的区域)。

## TTS(VoxCPM2)

随包 server 运行时在 [`voxcpm2-server/`](voxcpm2-server/)；GGUF 与声线库通过
`worlds.vtuber.tts*` 路径接入，空配置沿用原来的 `models/` 与 `voices/` 位置。

进程启停在「挂载」面板的「声音」那一行:spawn `llama-tts-server.exe`
([`tts-server.ts`](tts-server.ts),端口取自 `ttsUrl`);模组停止时连带停掉它拉起的进程。
其余操作在「声线档案」和「时间点标注」面板：

- **声线档案**:参考音频可「从本地导入」,缓存进配置的声线库目录(面板显示实际路径),
  也可直接选库里已有的;「试听参考」原声回放确认选对了人。带转写按续写克隆合成,
  只给音频是纯克隆。生成参数 `seed / cfg_value / inference_timesteps / max_steps / temperature`
  同面板可调。**「保存档案」是唯一的生效动作**:写回 config.json 的 `worlds.vtuber.ttsProfile`,
  同时把转写落成同名 `.txt` 侧车(下次选中这条声线自动带回来,清空转写就删掉侧车)。
  改了还没保存时面板会标出来——演出仍走已保存的那份。
- **参考音频转码**:VoxCPM2 的 `reference_audio` 只吃 wav,声线库因此只存 wav。
  导入 mp3 / m4a 这类压缩格式时,[`audio-convert.ts`](audio-convert.ts) 按文件头判型,
  再调本机 ffmpeg 转成 24kHz 单声道 PCM16(模型的原生采样率)。ffmpeg 与 `bin/` 里的
  二进制一样不入库:先找包内 `voxcpm2-server/bin/`,再找 PATH;都没有就只收 wav,
  报错里会说清缺什么。
- **单次测试**:输入任意文本合成试听(空 = 固定测试句),**就在本页播放**;
  声卡侧同步播出一份,顺带验证音频链路。试听按**面板上**的档案合成(不是已保存的那份),
  所以换声线可以先听再决定存不存;回执里会写明这一句用的是哪条声线。合成完「保存 wav」
  把这段音频存成本地文件(文件名带文本片段与时间戳),留着比对不同档案的效果。

脱离控制台手动起 server(冒烟、独立调试)见 [`voxcpm2-server/`](voxcpm2-server/) 的 README。

TTS 不做风格前缀注入。VoxCPM2 的 `(风格词)正文` 括号指令只在**只给参考音频**的可控克隆
模式下有效;这里用的是带转写的续写克隆(Hi-Fi,音色最接近),转写与参考音频逐字对应,
插进去的括号没有对应音频,模型只能把它念出来——放在句首、放在转写之前都一样。
标签因此只驱动动作与表情,不进 TTS。


## 片内时间点标注(Qwen3-ForcedAligner)

给每个 TTS 分片标出逐单元的起止时间:中文与日文逐字、英文逐词。实现在
[`align.ts`](align.ts),模型侧在 llama.cpp-omni 的 `tools/aligner/`,与 VoxCPM2 同进程
——一个 `llama-tts-server` 同时驮着 TTS 与对齐器,`POST /v1/audio/align` 收
(音频, 单元表),回每个单元的起止秒数。

模型是非自回归的:音频塔编码出的嵌入接进 Qwen3 0.6B 主干,单元文本之间插入成对的
`<timestamp>` 占位符,一次前向之后在每个占位符位置取隐状态,过 5000 类的时间桶头,
argmax 得到的桶号乘桶宽(80ms)就是时间。每个单元后面跟两个占位符,依次是起、止。
6 秒音频一次约 0.3–0.5 秒。

**单元粒度由调用方决定。** 模型支持任意粒度,但不会自己发现边界——喂什么粒度就标什么
粒度。`segmentUnits()` 的规则:

- 汉字、假名、谚文逐字;拗音(ゃゅょ)与长音符 ー 并入前一个字(同属一拍),
  促音 っ 单独成单元(它自成一拍,是一段有时长的闭锁)
- 拉丁、西里尔按空白与标点切词,词内保留连字符与撇号
- 标点与空白不参与:它们没有对应的发声段
- `[laughing]` 这类语气词**整体一个单元**:音频里它是一段真实发声,不给单元的话
  那段音频没人认领,覆盖率判据与相邻锚点都会被带偏。实测(8011,含 [laughing]/[sigh]
  的句子)邻字时间不受带偏,但语气词自身跨度偏窄、可能与邻字轻微倒挂,所以门里
  把它当**软单元**:只贡献覆盖率,不进倒挂/反向/零长计数

逐拍粒度与发声边界对齐,适合时间轴标记与口型驱动,并使管线保持为纯 JavaScript。

### 当作 TTS 的门

逐字稿与音频对不上时(VoxCPM2 漏字、复读、吞尾),对齐会退化。`judgeAlignment()` 看四项:
覆盖率(末单元终点 / 音频时长)、跨度反向(end < start)、时序倒挂(起点比前一个早),
以及零长跨度占比。阈值取自实测:同一段音频配正确逐字稿时倒挂与反向为 0、覆盖率 0.97,
故意配错逐字稿则分别是 0.26 / 0.11 / 0.34。

**对齐判废本身不触发破坏性动作。** 笑腔、拖音、语气词或含糊发声可使音频与逐字稿不匹配，仍可正常播放。判废时不采信单元表，字幕与 `<>` 锚点回落估计，并记录降级；重合成以超大静默段为判据（见下节）。对齐器不可用或报错时继续演出。

判废详情(`alignBad`)仍交给演出层,只为「撞上 server 32s 硬上限」那道最后兜底
提供切点:`lastGoodEndMs` = 垃圾段起点的估计。

### 错误生产:超大静默段

VoxCPM2 合出来「怪」的片有两类,处置相反。

**节目效果**包括笑腔、拖音和语速变化。这些特征或对齐判废本身不作为掐流、重合成或裁尾的依据。

**错误生产**的一种形态是解码未在句尾结束，输出长段连续近静默，阻塞后续音频队列；静默检测用于识别该信号。

两类的分界不在时长(长句本来就该念得久),也不在对齐(笑腔照样判废),而在
**音频里有没有一段连续死气**。破坏性动作只认这一个签名(`silence-scan.ts`):

```
静默判据 = 20ms hop 的 RMS < clamp(本片 p95 × 0.03, 0.003, 0.02)
超大     = 连续 ≥ 4000ms
```

相对项让整体小声的片不被整段误判;绝对下限 0.003(≈ -50dBFS,底噪量级)顶住
「整片都静默时 p95 自己也趋近 0」的塌陷;绝对上限 0.02 防住反向的一头。
4000ms 的依据是本仓库自己量过的停顿:句末 ~570ms、句中 ~200ms、语音标签 ~1500ms,
系统测出来的最长合法停顿是 1.5 秒,门是它的 2.7 倍。判据严格连续:中间夹一声杂音
就算两段,宁可漏不误伤。

三个触发点:

| 路径 | 条件 | 动作 |
| --- | --- | --- |
| 流式 | 收块过程中攒够连续静默(每 500ms 查一次) | 立即掐流;这一段还没开始播放就把死气从积压分块里裁掉,已在播就走音素感知切断,切点取静默起点 |
| 非流式 | 收到的整片里有超大静默段 | 换个采样重合成**一次**;两条都不干净取死气更短的那条,照常播出 |
| 兜底 | 对齐判废 + 流没被自己掐过 + 撞上 server 32s 硬上限 + 实测过预算 | 切掉未播出的尾巴。留着它是因为存在够不着静默门的形态:尾巴是连续杂音而不是死气 |

### 过长合成(时长兜底)

VoxCPM2 可能为短文本生成直到 server 时长上限的音频。观测样本中,二十余单元生成
32.0s 音频并占用 18-19s GPU;无效末段会阻塞后续队列并抬高积压估计。

合成流超过宽容界时中止收流，已收到的音频按原样播放；因时长预算被截断的片段不再进行第二次时长裁剪。

时长预算由台词文本、停顿先验和语速估计组成。单片自身的对齐末点或截断时长不能决定其破坏性阈值；语速来自同声线其他有效样本，样本不足时回落默认值。

#### 时长预算

```
预算   = (引子 500 + 单元数×速率 + 停顿) × 1.6
停顿   = 句末标点×570ms + 句中标点×200ms + 语音标签×1500ms
宽容界 = max(预算 + 4000ms, 预算 × 1.8)   ← 超过它才掐流
```

`速率` 由调用方显式传入，来源见「语速口径」。预算函数不读取实例状态，同一对（文本、速率）得到相同结果；调用方可使用同声线其他有效样本更新语速。

**宽容界**为 `max(预算 + 4000ms, 预算 × 1.8)`，用于限制持续发声的异常长片段。829 条净速率样本的实测/预算之比 p99 约为 1.38，1.8 倍界高于该正常长尾；普通的估计偏差不足以判定错误生产。静默段另由静默检测处理。

时序估计使用净速率 p75；宽容界用于限制异常长音频，不改变字幕时序的估计口径。

**停顿必须单独算**,因为 `segmentUnits` 把标点整个丢掉(它切的是"能对齐到音频的
单元"),而 VoxCPM2 把每个标点念成真停顿;语音标签在单元表里算 1 个单元(约 300ms),
实际却值一秒半。三个系数是 3245 片完整样本的最小二乘解
(时长 ≈ -92 + 257×单元 + 569×句末 + 195×句中 + 1572×标签),取整后用。

只按单元算的旧公式在同一批样本上掐掉 **125 片(3.7%)**,被掐的全是
「中间有坑过不去……垫过去。」这种标点多的正常话,和「对……」这种一个字带长拖音的
短句;加上停顿项之后同批 **0 片**被掐,而 8 单元的片真跑到 server 32s 上限时预算只有
约 6.1s,照样拦得住。

片段用满六成宽容界或被截断时，在 `[演出·TTS预算]` 中记录实测时长、预算、超出量、宽容界，以及采用的每单元时长和来源。

## 语速口径

字幕的估计档、跑飞门的预算、`<>` 锚点的估计死线、积压与回执的时长估计——**四处共用
一个 ms/单元**,来源是 `vtuber-diag/speech-rate.jsonl`:每片说话合成完(非流式的
`synth`、流式收流且未被掐的 `synthStream`)按 `{声线指纹, 单元数, 停顿源计数, 实测时长}`
追加一条(v2;v1 记录没有停顿计数,读取时跳过,换版本后当前声线冷启动一次),下次
开进程按当前声线恢复最近 64 条。**越播越准**。

估计使用**净速率的 p75**：`(实测时长 − 引子 500 − 停顿先验) ÷ 单元数` 的第 75 百分位。
估计式为 `引子 + 单元数 × 速率 + 停顿先验`；有效样本使用同一组先验扣除引子与停顿，预算计算再补回，使两项各计一次。v1 日志缺少当时的标点分项，不能直接用于这项停顿扣除。

取 p75 的理由:损失不对称,字幕早于嘴是剧透加观感坏掉,晚于嘴只是普通字幕延迟,所以
必须在中位以上;但取到尾部就把「早」换成更扎眼的「晚」,而且这个数同时是积压闸和
跑飞门的分母。829 条样本上净速率中位 305 / p75 417 / p90 531 / p95 627,
p75 正好是「典型片最多晚 1.7 秒 ≈ 慢片最多早 1.7 秒」的平衡点。

样本不足 12 条（冷启动、刚换声线或参考音频、诊断目录关闭）时，字幕、预算与锚点路径统一回落 `BUDGET_MS_PER_UNIT`。
使用估计的埋点记录当时采用的语速及其来源，供逐次复现计算。

## 流式输出与 <> 锚点(四组合)

`streamEnabled` × `alignEnabled` 两个开关拼出四种行为,运行时可用性压过开关
(server 没带对齐模型时锚点自动落到估计,不会去走剪切路;没有流式端点时回落整段):

| 流式 | 对齐 | <> 锚点怎么触发 |
|---|---|---|
| 开 | 开 | **目标形态。** 整片一段流;锚点时间三级来源:收流后全量对齐 > 播放中前缀对齐 > 估计死线 |
| 开 | 关 | 沿 <> 剪成子片队列,接缝处 fire-and-go(触发即播下一子片,不等动作做完) |
| 关 | 开 | 整片合成完先对齐再播,锚点直接按 units 时间点排 |
| 关 | 关 | 锚点按字符比例 × 片时长估计 |

目标形态的时间线(`orchestrator.ts` 的 AnchorRunner):

- **锚点 = 剥净标签后紧随其后那个单元的起点**,解析期就定下 charOffset,播放期换算成
  单元下标(`segmentUnits` 前缀计数)。
- **估计死线先武装**:`leadIn + unitIndex × msPerUnit`(引子 500ms 是常量,速率取
  「语速口径」那一份;整片取一次,片内不随样本增长漂移)。
  死线到达时仍无对齐结果则按估计触发。
  若前缀对齐正在执行，死线仅宽限一次 400ms。
- **前缀对齐抢跑**:已合成时长盖过估计位置 500ms、且离死线不到 2.5s 时,把已收的 PCM
  前缀连同截到锚点的单元表发一次 `/v1/audio/align`(RTF≈0.55 意味着合成头领先播放头
  的量随时间线性增长,一次 0.3-0.5s 的前向完全追得上)。合成期间 server 照常受理对齐
  (生成锁只锁 TTS runtime,对齐器自带锁),实测流毫无阻滞。
- **收流后全量对齐**一次解决所有未决锚点,顺带喂质量门。

真机 E2E(前缀对齐命中):「其实我今天没怎么<看一眼弹幕>没怎么吃饭吧…[sigh]
<看向屏幕>…」锚点分别落在播放位 3.2s / 6.8s,与语音位置吻合;开演到出声 0.4s。

流式片的句内韵律使用**增量扫描**(300ms 节拍,包络领先播放 1s+):与整段版的差异是
挤近时不回溯换更强的、强重音排名只对已见重音——流式下无法未卜先知,偏差在概率排程的
噪声量级内。

## 排队、打断与播放结果

认知时钟(LLM 轮,事件驱动)与嘴的时钟(1x 实时)天然不同步,session **永不阻塞**
等 TTS。堆积的语义只有两条出路:排队,或者由她自己打断。

- **`beginRound` 为追加语义**：新轮排在队尾，不修改在播或排队内容。同一条 assistant 消息中的多次 `vtuber_act` 视为同段话的分段，追加且仅豁免积压闸，仍受同轮 act 调用次数上限限制，tap 按轮边界计数。
- **积压闸**（`worlds.vtuber.speechCapSec`，默认 20s，x-hot）：跨轮新调用到达时，积压超限则拒收，不合成、不排队，回执明确该段未播出。积压量为在播片剩余时长加排队片时长，未合成片按当前语速估计；心跳的 `statusLine()` 提供本地演出状态。
- 更换话题通过 **`vtuber_interrupt`**，不自动抢占。工具等待收束完成（≤0.65s），并在结果事件持久化后返回回执。
- 打断栅栏固定为 tap 见到调用头时已创建的最后一个轮号（`Performer.roundFence()` → `preempt({ maxRoundId })`），不影响更晚的轮。同回复中后续 act 可经 tap 先于串行 interrupt handler 开始演出，栅栏保护这些新轮。

打断走**礼让式收束** `Performer.preempt()`:同步作废在队内容、掐断未开播的
合成(server 一个解码步内让出 GPU),正在播的片优先切在收束窗口内最近的自然停顿处
(相邻对齐单元间隙 ≥150ms),没有停顿就立即收——两种切点都走**音素感知切断**
(`interrupt-fade.ts`):从已合成的 PCM 上分类切点这一刻在响什么,按真人被打断的
收尾形态给衰减:

| 切点信号 | 普通话对应 | 判据 | 处理 |
| --- | --- | --- | --- |
| 周期 | 元音、m n l、韵母 | 归一化自相关在 60-400Hz 有强峰(≥0.5) | 指数衰减,4 个基音周期,钳在 20-70ms |
| 噪声 | f h x s sh、塞擦音的擦音段 | 非静音且无周期峰 | 指数快衰 20ms |
| 静音 | 塞音闭塞段、pause | 相对参考电平(前 1s hop-RMS p95)低 -20dB | 6ms 防点击收口;释放爆破在切点之后,不播出即不存在 |

分类看局部信号而不是音素字典身份,塞擦音"闭塞归闭塞、擦音归擦音"自动成立,英文/
假名/[laughing] 语气词一并覆盖。切点与衰减尾巴都用**片内采样坐标**表达:切断规划
从手上的 PCM 渲染尾巴,`device-audio.ts` 在样本队列的同一坐标上截停并拼接,波形
连续(切点提前量大于写入领先量,恒落在还没写进设备的区域)。

窗口 `worlds.vtuber.yieldWindowMs`(默认 500,x-hot;0 = 不找停顿立即收)可热调;
`worlds.vtuber.yieldFadeMs`(默认 150,x-hot)是**回落淡出时长**——PCM 不在手
或切点越过已合成末尾时退回整体线性淡出才用它。resolve 带回**外流账本**
(`RoundOutcome[]`:逐拍逐片"播没播、播到哪",切点按单元表反查字符偏移)。

模组依据账本追加 `vtuber.act.outcome` 事件，报告关联调用、演出轮次、本地已播放
台词和截断精度。原始参数与受理回执不变；词表外标记只在执行时清理，并在回执说明。
结果事件使用 external 来源、speak 标签与 flush 投递；不设置 ephemeral 或 snapshot。
中断回执等待音频收束和事件持久化，随后同轮的新台词仍可正常演出。

字符位置来自本地播放时钟。有对齐数据时按单元边界计算，否则按时长估算，
不代表观众端逐字接收确认。
旧修订侧车保留为只读档案；新的结果无需等待原调用进入 session。

控制台「时间点标注」面板可以选本地音频或现合一段来试,画出波络、时间刻度与逐单元色块,
播放时有扫描线,退化的单元换色标出。

模型文件与转换见 [`voxcpm2-server/`](voxcpm2-server/) 的 README。
