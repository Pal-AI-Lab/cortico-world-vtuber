# AI VTuber 演出模块设计方案

事件驱动的演出模块:消费上游事件(弹幕、游戏事件),输出混编 TTS 语音与 Live2D 动作的连续演出。

## 0. 总览

```
事件流 ─→ [调度 Core] ─→ LLM ─→ 标签脚本流
                                      │
              ┌───────────────────────┘
              ▼
  L2 编排器: 解析 → beat 队列 → State 状态机 / Pulse 排期 → cue
              │                                    │
              ▼                                    ▼
         TTS 流水线                            L3 混音台 (60Hz)
              │                                    │
              ▼                                    ▼
           音频播放                    L4: IR 帧 → VTS 注入
```

分层纪律:**语义与时间止步于 L2,参数始于 L3**。

- L1(agent):决定演什么。只见词表与文本,不见任何数值。
- L2(编排器):决定何时。持有全部时间结构与状态机,不知任何 Live2D 参数。
- L3(混音台):决定参数值。逐帧求值与仲裁,不知时间结构与语义。
- L4(backend):IR → VTS 注入,无状态管道。

L1 的词表与 L3 的曲线资产合起来是**演出包**(`vocab.json` + `clips.json`),归 bot 所有,
以 `packDir` 传给 World(缺省用 `examples/vtuber-pack/`);L2/L3 代码不认识任何具体的词或 clip,
只按包里的 `(channel, clipId, lifecycle)` 与曲线工作。

反向可检验性:换 backend 只动 L4;换脚本语法只动 L2 前端;未来接 actor 小模型 = L2 多一个 cue 生产者。

## 1. L1:提示词与工具

### 1.1 系统提示词(演出部分,全文)

> 你是虚拟主播小雾,正在直播下棋,一边玩一边和弹幕聊天。说话口语化,像真人主播,句子短,可以有语气词。
>
> 你说的话会直接变成语音,同时你可以在话里夹【】来做表情和动作。规则:
>
> 【】里可以写这些词,用逗号隔开,想用几个用几个:
> - 动作(做一下就结束):点头、摇头、惊吓后仰、垂头丧气、歪头疑惑、翻白眼、得意、愣住、瞪大眼睛、看一眼弹幕
> - 姿态(会保持一阵子):歪头、轻轻摇摆、前倾
> - 表情(会挂在脸上,直到你换):微笑、大笑、生气、可怜、害怕、感动
> - 看向(视线会停在那):看向屏幕、看向弹幕、看向镜头、看向下面
> - 特效(头上/脸上弹出的小挂件,弹一下就消失):惊讶特效、流汗特效、灯泡特效、问号特效、星星特效、加载中特效、脸红特效、怒气特效、叹气特效、眼镜特效
> - 【Reset】:一切回到平常的样子
>
> 怎么用:
> - 空的【】就是单纯断句换气,多数时候用这个就行
> - 表情和姿态设了就会一直在,不用每句都写,情绪变了再换
> - 不用堆砌,一大段话里点缀两三次就够,平淡的话完全不加也可以
> - 说到情绪转折的地方再加,加在转折那个字的前面
> - 标签单独占一行、后面空着,表示先做动作停一拍再开口
> - 【】里只能用上面列出来的词,写别的系统不认识,等于白写
> - 没什么可说的时候可以不说话,只做个动作、看看弹幕,甚至什么都不输出,这很正常
> - 超过二十秒的弹幕要么不回,要回就带上"刚才有人说"这类话头
>
> (例子:沿用已验证的下棋场景示例)

### 1.2 工具定义

Core 内演出模块只暴露一个工具;游戏操作等其他工具与其并行,不在本模块范围。

**`vtuber_act(script: string)`**
- script 为混编台本(标签脚本流)。空串不是"主动沉默":它一个字也播不出去,回执按失败形报,并点名 script 是空的。
- **流式捕获**:World 识别到工具调用头即开始捕获参数文本流,逐字符送入 L2 解析器;不等待调用完成。解析、TTS 分片、演出与 LLM 生成全程流水线化。
- 每次调用输出 **2–4 个 beat**,由提示词约束("说两三句就停下看看情况")。

### 1.3 事件注入格式

- 弹幕:带用户名,逐条落一条事件;合批交给 Core 的安静窗口与地板,World 不自己攒。
- 游戏事件:文本化的局面描述与事件(对方落子、将军、认输等)。
- 系统状态:当前模式、正在播放/排队的语音概要(供模型衔接语义)。

## 2. 标签词表(L1↔L2 契约)

### 2.1 通道 × 生命周期矩阵

词表的权威版本是 bot 演出包的 `vocab.json`(范例在 `examples/vtuber-pack/`),这里只给通道 × 生命周期的结构(词会持续增补):

| 通道 | Pulse(触发即忘) | State(保持至替换/超时/Reset) |
|---|---|---|
| Gesture/Pose(身体) | 点头(含用力/连连强弱档)、摇头(含拼命档)、惊吓后仰、垂头丧气、歪头疑惑、翻白眼、得意、愣住、瞪大眼睛、看一眼弹幕、环顾四周、雀跃、鼓脸颊、眨单眼 | 歪头、轻轻摇摆、前倾、抬头挺胸 |
| Gaze(注视) | 看一眼弹幕(gesture pulse) | 看向屏幕、看向弹幕、看向镜头、看向下面、看向斜上方 |
| Emotion(面部) | — | 微笑、大笑、生气、可怜、害怕、感动、惊讶、困倦 |
| FX(特效) | 惊讶特效、流汗特效、灯泡特效、问号特效、星星特效、加载中特效、脸红特效、怒气特效、叹气特效、眼镜特效 | — |

- 每词条静态携带 `(channel, clip_id, lifecycle)`(可选幅度档 intensity),解析瞬间确定,运行时不再查词。
- 强弱档 = 同一 clip 不同 intensity 拆成的多个词(用力点头 ×1.35),给 L1 一个幅度旋钮而不引入新语法。
- `Reset`:清空全部 State 通道,回待机。
- 空【】:纯 beat 分隔,不触碰任何通道。

### 2.2 别名表

解析期归一化,持续从测试日志增补。初始:凑近/靠近→前倾,认真→前倾,晃脑袋→轻轻摇摆,委屈→可怜,呆住→愣住。

### 2.3 未知标签

静默丢弃。**任何标签文本绝不进入 TTS。**

### 2.4 TTS 风格前缀映射

> **未实现。** 括号指令只在只给参考音频的可控克隆下有效;演出用的是带转写的续写克隆
> (Hi-Fi),转写与参考音频逐字对应,插进去的括号没有对应音频会被逐字念出来(位置无关)。
> 两者不可兼得,取音色。下表留作设计记录。

多对一映射至**实测筛选过的封闭风格词表**;右列词条以 VoxCPM2 试听结果为准(筛选主要淘汰标准:片间音色一致性)。

| 来源标签 | 风格词(暂定) | 作用域 |
|---|---|---|
| 微笑/大笑 | 开心/大笑 | State:该 Emotion 活跃期内的每个分片 |
| 生气 | 生气 | 同上 |
| 可怜 | 失望低落 | 同上 |
| 害怕 | 惊慌 | 同上 |
| 感动 | 感动 | 同上 |
| 惊吓后仰 | 惊慌 | Pulse:仅紧随标签的一个分片 |
| 垂头丧气 | 失望低落 | 同上 |
| 瞪大眼睛/愣住 | 惊讶 | 同上 |
| 得意 | 得意 | 同上 |
| 翻白眼 | 无语 | 同上 |
| 其余全部(Gaze/Pose/点头/摇头/歪头疑惑/fx) | 无 | — |

规则:
- 分片合成时注入**该分片开始时刻**状态机内活跃 Emotion 的风格词(读状态机,不读文本位置)。
- 同分片 Pulse 声线压过 Emotion 声线,仅该片,下一片回落。
- 前缀 1–2 词,禁止拼接复合前缀。

## 3. L2:编排器

### 3.1 流式解析器

- 逐字符扫描 LLM 输出流；`【…】` 为指令块，块后文本累积为 speech。
- **Beat(unit)= 一个指令块 + 其后直到下一指令块的文本**；文本可为空（纯演出 beat）。
- speech 累计至少 40 字后遇句末标点（。！？!?…）即切一片送 TTS 预合成；连续标点与闭引号归前片。`【】` 边界与流末不受字数门槛限制，残余文本照常发出；预取领先 1–2 片。已送入 TTS 的片段在后续打断时不可回收。
- 锚点：beat 的 `speech_start` = 首片音频开始，`speech_end` = 末片结束。
- 容错：残缺标签丢弃并剥离；标签词按词表与别名表匹配，顺序无关；缺席时使用默认值。

### 3.2 State 状态机

每个 State 通道(Pose / Emotion / Gaze)一个**长驻状态机**,beat 仅向其发事件;非逐单元传递。

- 转移:设置 → fade_in ≈ 300ms crossfade;同通道新值直接 crossfade;重复设当前值重发 cue(爆发型 sustain 分量重新起势);超时缓慢衰减回中性(2–3s 淡出);Reset 全清。
- 超时:默认 Gaze 4–6s,Pose 10–15s,Emotion 20–30s;可在控制台 World 配置里按通道热调(`worlds.vtuber.decay*Sec`)。
- crossfade 由 L2 在 cue 中声明(`fade_in` 字段),L3 执行,L2 不逐帧计算。

### 3.3 时序:speech_onset 与 gap

- 每个 pulse clip 资产携带元数据 `{duration, speech_onset}`(手调常数);Gaze 转移 onset ≈ 转头行程 70%;Pose/Emotion/fx 的 onset = 0。
- beat 语音开始时刻 = 上片音频结束 + gap:

```
gap = max( boundary_base, max(本beat各标签 speech_onset) )
实际gap = max( gap, 下一片音频就绪时刻 − 上片结束时刻 )
```

- boundary_base:同行标签块 ≈ 100ms;换行 ≈ 400ms;上片以……结尾 → 实测 TTS 是否已渲染尾停,未渲染补 ≈ 300ms;**行尾孤立标签 → 该标签完整 speech_onset 不打折**(演出先行)。
- 全局 gap 上限 1.2s;±10% 随机抖动。

### 3.4 同拍次序与打断

- 同拍含 State 与 Gesture:State 先起 crossfade,Gesture 延迟 ≈ 300ms 触发。固定策略,不暴露给 L1。
- 新一轮输出到达:默认排队——当前句说完、清剩余 pending、开新轮。硬打断仅限显式高优先级事件:音频 ≈ 150ms fade,gesture crossfade,State 通道保留。
- 纯动作 cue 永不排队等语音,按锚点照常触发。

### 3.5 cue 输出格式(L2→L3 契约)

```
{ channel, clip_id, start_ts, intensity, fade_in }
```

引用 clip_id,不内联曲线。cue 流可 dump、可重放,作为演出记录与调试手段。

### 3.6 调度 Core

拉起 LLM 的节奏归 bot 侧的心跳(装配层在演出链路起着时给 `tickDelayMs` 提速到秒级
快拍,心跳文案带演出状态行,嘴空没空她自己看);弹幕与游戏事件照常走事件投递。
World 不额外造唤醒时机。

允许空输出(沉默合法)。

### 3.7 说话的节奏

新台词一律追加,不自动抢占。积压超过 `speechCapSec` 时拒收并返回未播出回执;
更换话题必须显式调用 `vtuber_interrupt`。

### 3.8 语音伴随(不经 LLM)

- TTS 播放中按重音排韵律头动与抬眉(见 §4.2 第 4 条),不叠固定正弦律动;停顿后
  再开口时提前触发 speech_onset 句首头部模式。
- 不经 LLM 的层只跟语音的物理量(重音、起声)与生理(眨眼、注视保持—突跳)走,
  不表达对任何事件的态度。对事件的一切反应——瞟一眼、瞪眼、前倾——都出自台本,
  机械层不掷骰子替她演戏。

### 3.9 双时钟与播出延迟

- OBS 对游戏画面(**含游戏音频**)设固定延迟 N 秒;Live2D 与 TTS 不延迟。
- N 取延迟分布(prefill + 首 beat 生成 + TTFA)的 **P10–P20 分位**(宁小勿大,禁止反应先于事件)。
- 配置两个值,都归 vtuber World:`obsDelaySec`(OBS 里设的 N)与 `delayedSources`
  (被延迟画面对应的 World id 数组)。不需要任何游戏→演出的旁路信号:排演出时向
  Core 的事件库反查 `source ∈ delayedSources` 且 `ts > now − N` 的事件,
  **演出锚点 ≥ 事件时刻 + N + ε**。只消费信封的 core 字段(source/ts),不读正文、
  不认识游戏词表;比 now−N 更老的事件给出的地板在过去,扫描天然有界。
- 地板钳制所有输出、不做因果归因:判断"这段话是不是在说游戏"不可靠,而 N 只有
  秒级,一刀切最多让无关的话晚零点几秒,换来永不穿帮。

## 4. L3:混音台

### 4.1 混合模型

60Hz 逐帧求值。**每个参数**一条固定混合链:

```
param = clamp( base(idle) + Σ 各通道加性偏移 ) ,或被 override 抢占
```

- 通道与参数**多对多**;通道是行为语义单位,参数是物理资源,同参数多通道同时写为常态。
- override 仅限:lipsync(嘴部,最高优先)、gaze 眼球;头部一律加性。
  **眼睑走"idle 为主、表情帧接管"**:VTS 输入参数 `EyeOpen` 无追踪时基线是 0,
  "正常睁眼"落在输入区间的哪个值由模型作者的映射决定;IR 里的眼睑偏移在 L4 按
  模型档案 `wiring` 的 `neutral + 偏移 × scale` 换算成绝对输入量。被接管的帧由 L3
  补眨;无眼睑写入的帧完全不碰,眨眼归 idle 动画(档案 `idleBlinks: false` 的模型
  则由 L3 全程持有)。实证与机制见 README「眼睑:idle 为主,表情帧接管」。
- L4 只发**实机认识的**输入参数(连接时查 `InputParameterListRequest`):注入不存在的参数
  会让整条注入请求被拒,连同正常参数一起丢。
- Sidechain ducking:pulse 触发时,同参数上 State 贡献压至 ≈ 30%,pulse 结束后 ≈ 1s 恢复。
  进入与恢复均使用斜坡（压入 ≈135ms、恢复 ≈1s），避免单帧参数跳变。

### 4.2 通道栈(低→高)

1. Idle 基座:VTS 侧待机——**呼吸与眨眼都归它**。注入端恒发 `faceFound: false`,
   VTS 因此一直放内置的 tracking-lost idle 动画,眨眼由那个动画提供(详见 README
   「眨眼:归 VTS,不要碰」)。
2. State 通道:Pose / Emotion / Gaze 保持值。
3. Gesture:加性一次性轨迹。
4. 韵律:同 Gesture 的资产格式与加性叠加,但**不参与 ducking**——句首头动与重音头动
   一句里要来好几次,若压低同参数的 State 贡献,保持姿态会被反复抽掉再恢复。
   由 L2 从 TTS 振幅包络里找重音后预排(抬眉必须早于重音,不能在线检测)。
   说话时的头动**不做固定正弦律动**:0–2Hz 是与语音无关的姿态漂移带(归 idle/摇摆),
   与韵律相关的是 2Hz 以上那层,且必须做成事件级——语音→头动本质欠定,
   连续映射最多复现一半方差。详见 README「韵律层」。
5. FX:Expression/Hotkey 定时脉冲(开→持续→关)。
6. Lipsync:TTS 驱动,嘴部 override。

### 4.3 资产格式(三种)

- **Pulse 轨迹**:多关键帧完整曲线(去-回-回弹),终点回 0;元数据 `{duration, speech_onset}`;支持 intensity 缩放。
- **Sustain 三段式**:进入曲线 → 保持位(叠低频微噪声,防定格)→ 退出曲线。
- **Controller**(无资产):Gaze 在线生成,按眼动生理学的**保持—突跳**序列而非平滑趋近——
  注视时长取 ex-Gaussian、换位走扫视主序列、注视期叠慢漂移,游走半径由目标声明
  (`scanRadiusDeg`,即"要看的这块东西"的视角大小)。头跟眼、滞后起动且幅度衰减不追到底,
  头部贡献走加性。眼在头内 = 总视线 − 头已转过的部分,由此自然得到"眼先冲到位 →
  头跟上 → 眼回中"与大幅转向的阶梯式行为,无需单独的 VOR 状态机。
  参数与文献出处见 README「注视模型」。

### 4.4 输出

每帧输出**全量快照** IR(所有受控参数当前值),L3 之后无增量语义。

## 5. L4:IR 与 backend

- **IR = Live2D 标准输入参数字典 + add/override 标记**(AngleX/EyeOpenL 层级;绝不触及 deformer/part 层)。v1 直接采用 VTS 输入参数命名。
- L4 职责:打包 `InjectParameterData` 逐帧发送、WebSocket 会话管理、**持续注入保活**(VTS 停发约 1s 后 idle 动画抢回参数;add 的基准是输入参数基线,**不是**叠在 idle 输出之上——被注入的参数 idle 让位,所以头部三轴由 L3 全时持有、环境漂移垫底);FX 转发为 Expression/Hotkey 调用并定时关闭。
- L4 不持演出状态,只有传输节流(双帧流水 + 最新帧候补);丢帧下一帧自愈。
- **模型档案**是 L4 的数据面:语义量→实机输入量的换算(`wiring`:中性位、增益、
  钳位、取反、改发别的输入)、不支持的参数、FX 标签→表情文件与时长的表、启动复位
  保留的表情、idle 是否眨眼。档案是模型目录里的 `cortico.profile.json`
  (`<live2dDir>/<模型目录>/`),与模型文件一起走,仓库不含任何模型的档案或数值;
  `models/` 只有契约、校验、发现、复检与自检。连接时与 VTS 切换模型时按配置 id 或
  模型名定档,未识别的模型用默认档案(Cubism 模板接线,无 FX)。契约见 README「模型档案」。
  未来换 backend = 档案里换一个 `backend` 值 + 注入方式适配。
